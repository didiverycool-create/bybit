# 架构总览

## 产品定位

本项目的 v1 是“Bybit 桌面版量化交易控制端”。

它的职责是：

- 统一查看实时行情、K 线、自选和持仓状态
- 管理策略、参数、风控、回测及回测结果
- 控制 OpenClaw 调度流程，包括暂停、终止、人工接管、冻结自动发布
- 查看新闻、提醒、AI 执行记录、AI 复盘和系统审计

它**不是**交易执行引擎本身。

## 四层结构

### 1. 桌面控制端

路径：`apps/desktop`

职责：

- 提供中文桌面 UI
- 展示总览、行情、策略、回测、AI 调度、新闻、提醒、交易记录、AI 复盘、审计
- 把用户操作转换为结构化请求
- 保存工作台状态，例如默认页面、布局方案、总览卡片显示顺序
- 不直接持有 Bybit API Key 或 OpenClaw token

### 2. 量化核心服务

当前阶段由 `services/control-api` 中的 mock 服务承接接口形态，后续会替换为真实量化核心适配层。

最终职责：

- 管理账户、持仓、订单、成交、资金同步
- 执行手动交易与自动交易
- 统一风控门禁
- 统一策略运行时、模拟盘、Demo、实盘
- 管理回测任务和结果

当前阶段已部分真实化：

- 行情接口优先接 Bybit 公共 REST API
- 账户视图可通过 Bybit 私有 API 读取只读账户、持仓和未成交委托
- 私有交易 POST 链路可通过安全探测接口验证签名、认证和交易权限
- 当外部行情不可用时，自动回退到本地 mock 数据

### 3. OpenClaw 编排层

OpenClaw 作为外部本机系统接入，不修改其源码。

职责：

- 读取结构化任务
- 执行复盘、总结、调参、任务编排、状态回写
- 管理 AI 调度队列和执行记录
- 不能直接绕过量化层访问交易执行接口

### 4. 本地存储与审计层

当前位于 `services/control-api/.runtime/state.json`，用于保存 mock 状态。

长期职责：

- 保存 ChangeRequest、AgentJob、BacktestRun、ExecutionEvent 等核心数据
- 保存配置快照、策略版本、参数版本、回测结果
- 为审计与历史追踪提供统一事实来源

## 关键边界

### 前端与交易执行的边界

- 前端负责控制和展示
- 交易最终执行由量化层完成
- 手动交易不能经过 OpenClaw 决策

### OpenClaw 与量化层的边界

- OpenClaw 负责编排和执行管理任务
- OpenClaw 不能直接下单
- OpenClaw 不能绕过风控
- OpenClaw 只能消费结构化任务，不直接解析 UI 页面做隐式决策

### 网页入口与 API 入口的边界

- 浏览器登录、账户设置、API Key 创建等网页操作统一使用 `https://www.bybit-global.com/`
- 程序调用的行情、交易、公告接口使用 Bybit API 域名
- 如果文档里同时出现网页域名和 API 域名，必须明确说明用途不同

## 核心数据流

### 1. 前端配置修改

`桌面端操作`  
-> `生成 ChangeRequest`  
-> `OpenClaw 消费并落实`  
-> `状态写回本地服务`  
-> `前端刷新 Actual State`

### 1.1 工作台状态保存

`桌面端调整布局/模式/默认页面`
-> `先写入本地缓存`
-> `同步到 /api/workspace/preferences`
-> `本地控制服务持久化`
-> `新会话或后续 AI 接手时恢复工作台状态`

### 2. AI 调度控制

`桌面端发出 SchedulerCommand`  
-> `本地服务记录调度命令`  
-> `OpenClaw 执行调度动作`  
-> `调度状态与审计事件回写`

### 3. 手动交易

`桌面端手动下单`  
-> `量化层风控校验`  
-> `量化层执行交易`  
-> `订单/成交/审计事件回写`

当前实现说明：

- v1 当前只开放 Paper 模式的手动交易录入
- Demo / Live 仍保留在产品架构中，但还没有接通真实执行引擎
- 控制端会明确提示这条边界，避免把 mock 或占位能力误认为真实下单

### 4. 自动交易

`策略运行时生成信号`  
-> `量化层风控校验`  
-> `量化层执行交易`  
-> `结果进入审计和 AI 复盘上下文`

### 5. 公共行情接入

`桌面端请求 watchlist / market detail`
-> `本地控制服务优先请求 Bybit 公共 REST`
-> `成功则返回真实行情`
-> `失败则回退本地 mock`
-> `前端继续保持同一套契约展示`

## v1 与 v2 的边界

### v1

- 只做桌面端
- 先用本地控制服务 mock 数据跑通完整控制链路
- 优先保证中文控制台、结构化任务、AI 调度硬中断和审计链路

### v2

- 复用领域契约做 Web 端
- 接入真实量化核心
- 接入真实 OpenClaw 工作流与生产化通知
