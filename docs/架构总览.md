# 架构总览

## 产品定位

本项目的 v1 是“Bybit 桌面版量化交易控制端”。

它的职责是：

- 统一查看实时行情、K 线、自选和持仓状态
- 管理策略、参数、风控、回测及回测结果
- 控制 OpenClaw 调度流程，包括暂停、终止、人工接管、冻结自动发布
- 查看新闻、提醒、AI 执行记录、AI 复盘和系统审计

它**不是**交易执行引擎本身。

## 四层结构

### 1. 桌面控制端

路径：`apps/desktop`

职责：

- 提供中文桌面 UI
- 展示总览、设置、行情、策略、回测、AI 调度、新闻、提醒、交易记录、AI 复盘、审计
- 把用户操作转换为结构化请求
- 保存工作台状态，例如默认页面、布局方案、总览卡片显示顺序
- 不直接持有 Bybit API Key 或 OpenClaw token

当前前端信息架构补充说明：

- 首页 `总览` 是“运行看板”，不是控制面板
- 首页优先展示量化交易进行中最关注的点：主图表、自选观察、AI 当前状态、仓位和风控摘要、最高优先级提醒
- 首页当前按“图表主舞台 + 左侧自选观察 + 右侧运行轨 + 底部终端式面板”组织，参考了 TradingView 将图表放在中心、研究与日志下沉到底部的布局思路
- 控制动作、模式切换、布局管理、首页模块开关统一收进 `设置` 页面
- 左侧导航的大模块当前保持整页切换；后续弹窗优先用于模块内部的次级操作、详情和临时控制窗口
- 左侧导航按“交易观察 / 策略研究 / 运行控制 / 记录审计”分组，避免功能平铺堆积
- `策略`、`回测`、`AI复盘` 三页当前已通过 AI 提案动作联动，提案接受后可进入 ChangeRequest 或直接生成回测记录
- `策略` 页当前已支持直接编辑参数和风险预算；在 mock 阶段，这些变更会先写成 ChangeRequest，再由本地 mock 编排器自动落实并回写
- `策略` 页当前已开始接入最小策略运行态，可看到当前信号、置信度、参考价和下一步动作；`paper` / `paper_only` 策略会补纸面成交记录
- `回测` 页当前已支持按策略筛选结果、配置周期与区间发起回测，并在详情侧查看参数快照与当前策略差异
- `回测` 当前会自动排队 `generate_backtest_review`，由 OpenClaw worker 继续生成“回测 AI 复盘”并写回提案

### 2. 量化核心服务

当前阶段由 `services/control-api` 中的 mock 服务承接接口形态，后续会替换为真实量化核心适配层。

最终职责：

- 管理账户、持仓、订单、成交、资金同步
- 执行手动交易与自动交易
- 统一风控门禁
- 统一策略运行时、模拟盘、Demo、实盘
- 管理回测任务和结果

当前阶段已部分真实化：

- 行情接口优先接 Bybit 公共 REST API
- 行情主链路当前已开始优先接 Bybit 公共 WebSocket，REST 继续承担首帧与回退
- 账户视图可通过 Bybit 私有 API 读取只读账户、持仓和未成交委托
- 私有账户视图当前也会优先使用 Bybit 私有 WebSocket 只读缓存补齐总览、持仓、委托与最近成交
- 当前已补了最小策略运行时，会基于最新行情生成运行信号，并为 `paper` / `paper_only` 策略写入纸面成交
- 私有交易 POST 链路可通过安全探测接口验证签名、认证和交易权限
- 当外部行情不可用时，自动回退到本地 mock 数据

### 3. OpenClaw 编排层

OpenClaw 作为外部本机系统接入，不修改其源码。

职责：

- 读取结构化任务
- 执行复盘、总结、调参、任务编排、状态回写
- 管理 AI 调度队列和执行记录
- 不能直接绕过量化层访问交易执行接口

当前补充：

- 已有本机 OpenClaw worker 自动认领 `AgentJob`
- 当前已覆盖日度复盘与回测复盘任务
- `cancel_job`、`cancel_all`、`enter_manual_override` 会真实终止当前 OpenClaw 任务

### 4. 本地存储与审计层

当前位于 `services/control-api/.runtime/state.json`，用于保存 mock 状态。

长期职责：

- 保存 ChangeRequest、AgentJob、BacktestRun、ExecutionEvent 等核心数据
- 保存配置快照、策略版本、参数版本、回测结果
- 为审计与历史追踪提供统一事实来源

## 关键边界

### 前端与交易执行的边界

- 前端负责控制和展示
- 交易最终执行由量化层完成
- 手动交易不能经过 OpenClaw 决策

### OpenClaw 与量化层的边界

- OpenClaw 负责编排和执行管理任务
- OpenClaw 不能直接下单
- OpenClaw 不能绕过风控
- OpenClaw 只能消费结构化任务，不直接解析 UI 页面做隐式决策

### 网页入口与 API 入口的边界

- 浏览器登录、账户设置、API Key 创建等网页操作统一使用 `https://www.bybit-global.com/`
- 程序调用的行情、交易、公告接口使用 Bybit API 域名
- 如果文档里同时出现网页域名和 API 域名，必须明确说明用途不同

## 核心数据流

### 1. 前端配置修改

`桌面端操作`  
-> `生成 ChangeRequest`  
-> `OpenClaw 消费并落实`  
-> `状态写回本地服务`  
-> `前端刷新 Actual State`

当前 mock 实现补充：

- 为了让桌面端开发阶段具备可验证的闭环，常见策略类 ChangeRequest 会由本地 mock 编排器立即落实
- 正式量化核心接入后，这一步会逐渐替换为真实 OpenClaw 编排与量化内核协作链路

### 1.1 工作台状态保存

`桌面端调整布局/模式/默认页面`
-> `先写入本地缓存`
-> `同步到 /api/workspace/preferences`
-> `本地控制服务持久化`
-> `新会话或后续 AI 接手时恢复工作台状态`

### 2. AI 调度控制

`桌面端发出 SchedulerCommand`  
-> `本地服务记录调度命令`  
-> `OpenClaw 执行调度动作`  
-> `调度状态与审计事件回写`

当前实现补充：

- 调度器处于 `running` 时，worker 会自动认领队列中的 `AgentJob`
- `manual_override` 会冻结自动发布，并终止当前正在执行的 OpenClaw 任务

### 2.1 AI 提案执行

`AI复盘页 / 策略页接受提案`
-> `POST /api/ai/proposals/{proposal_id}/action`
-> `根据提案类型生成 ChangeRequest 或回测`
-> `状态写回 reviews / backtests / change_requests / audit`
-> `首页与策略工作台刷新`

### 3. 手动交易

`桌面端手动下单`  
-> `量化层风控校验`  
-> `量化层执行交易`  
-> `订单/成交/审计事件回写`

当前实现说明：

- `POST /api/trades/manual` 当前仍只负责 Paper 模式的直接成交写入
- Demo / Live 当前已经接通真实委托、改单、撤单、全撤与真实策略自动执行的基础链路，但仍在继续往统一生产级执行内核收口
- 控制端会明确区分 Paper 直接成交、真实委托接口与策略自动执行路径，避免把不同执行链路混为一类

### 4. 自动交易

`策略运行时生成信号`  
-> `量化层风控校验`  
-> `量化层执行交易`  
-> `结果进入审计和 AI 复盘上下文`

### 5. 公共行情接入

`桌面端请求 watchlist / market detail`
-> `本地控制服务优先请求 Bybit 公共 REST`
-> `成功则返回真实行情`
-> `失败则回退本地 mock`
-> `前端继续保持同一套契约展示`

## 当前阶段边界

- 只做桌面端，不再为 Web 端排期
- 继续沿用现有领域契约与页面结构，把桌面端补到更接近生产可用
- 优先把真实量化核心、真实执行风控、OpenClaw 编排闭环和桌面壳体验做实
