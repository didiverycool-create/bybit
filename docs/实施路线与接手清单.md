# 实施路线与接手清单

本文档用于帮助后续 AI 会话、Codex 新线程或人工开发者快速判断“当前做到哪了、下一步该做什么、哪些边界不能碰”。

## 1. 当前产品定义

- 产品名称：Bybit 桌面版量化交易控制端
- v1 只做桌面端，不交付 Web 端
- 前端职责是观察、控制、审计、干预
- 自动交易最终执行仍归量化层
- OpenClaw 只做编排、复盘、调参、任务执行与状态回写

## 2. 当前代码现状

### 已落地

- `apps/desktop`
  - 已有 React + TypeScript 控制端界面
  - 已用 Electron 作为当前桌面壳
  - 已有总览、行情、策略、回测、AI 调度、新闻事件、提醒中心、交易记录、AI 复盘、系统日志/审计页面
  - 已有本地 API 调用层与 fallback 数据
  - 行情页已支持自选管理二级窗口，可增删关注品种
- `services/control-api`
  - 已有 FastAPI 本地控制服务
  - 已有 `ControlSnapshot`、`ChangeRequest`、`AgentJob`、`BacktestRun`、`ExecutionEvent` 等模型
  - 已有本地 JSON mock 状态仓储
  - 已有 `WorkspacePreferences` 工作台状态持久化
  - 工作台状态当前会保存主盯盘 K 线周期，桌面端重开后会恢复上次选择的 `15m / 1h / 4h / 1d`
  - 工作台状态当前也会继续保存回测页聚焦回测、`仅当前策略/全策略` 回测筛选、复盘跟踪范围，以及提醒/成交/审计筛选器与审计搜索词，便于跨重启和新线程延续排障上下文
  - Electron 主窗口当前也会保存大小、位置和最大化状态；若历史坐标已落到当前不可见显示器区域，启动时会自动回退到安全默认窗口
  - 已有 Bybit 公共 REST 行情适配
  - 已开始用 Bybit 公共 WebSocket 驱动 watchlist ticker 与主图最新 K 线，REST 继续承担首帧和兜底
  - 行情详情当前已支持 `15m / 1h / 4h / 1d` 多周期切换，其中 `1h` 会优先用公共 WebSocket 合并最新 K 线，其余周期当前走 REST 历史数据
  - 已有 `/api/market/live` 近实时聚合行情快照，用于总览页和行情页联动刷新
  - 已把 Bybit 公共最近成交接入 `MarketDetail.recent_public_trades`，用于桌面端最近成交面板
  - 已把 Bybit 公共盘口快照优先接到 `MarketDetail.bids / asks`，桌面端盘口与最近成交现在同样优先走公共 WebSocket
  - 已给自选品种补上独立提醒阈值与提醒开关，超阈值后会自动生成去重后的市场提醒
  - 已给自选提醒规则补上 `AlertRule` 跟踪、冷却时间和最近触发记录，当前可通过 `GET /api/alert-rules` 查询
  - 已有 `/api/ai/live` 近实时聚合调度快照，用于总览页和 AI 调度页联动刷新
  - 已有 `/api/ops/live` 近实时事件快照，把提醒、成交和审计事件统一成一套来源
- 已有 `/api/account/live` 近实时账户快照，把账户总览、持仓、未成交委托和历史订单统一成一套来源
- `GET /api/account/overview`、`/api/account/live`、`/api/account/positions`、`/api/account/orders`、`/api/account/order-history` 当前也支持可选 `mode` 查询参数，可在不改工作台 `selected_mode` 的前提下直接诊断另一套账户视图
- 未配置 Bybit 私有 Key 且当前模式为 `paper` 时，账户总览与持仓当前会由本地 Paper 成交动态派生，不再使用固定 mock 账户
- 未配置 Bybit 私有 Key 且当前模式为 `paper` 时，历史订单当前也会由本地 Paper 成交动态派生
  - `GET /api/account/positions` 在真实模式下当前也会用钱包 `coin[]` 自动补出 `spot` 持仓；若交易所显式持仓里已包含同一现货资产，则会自动去重
  - 已有 `/api/account/order-history`，用于读取 Bybit 私有侧最近历史订单，便于后续做更细的交易记录窗口
  - 已有 `/api/strategies/live`，用于返回最小策略运行态，并为 `paper` / `paper_only` 策略补纸面成交
  - `/api/strategies/live` 当前也会附带 `execution_preview`，把当前策略信号若继续按 `paper` 执行时的仓位变化、余额变化和阻断原因一并返回
  - 当工作台当前模式切到 `live/demo` 且策略模式匹配时，`/api/strategies/live` 现在也会直接附带对应的真实顾问式执行预检
  - 若后台 `strategy runtime` 线程当前异常或停滞，`/api/strategies/live` 与 `GET /api/strategies/{strategy_id}/execution-preview` 当前都会直接返回阻断态预检，运行态现有的 `guard_state / guard_detail` 也会同步标成“执行受阻”
  - 若后台 `strategy runtime` 线程已停止但此前曾成功刷新过，当前也会与异常/停滞一样进入真实执行门禁；策略级预检、运行态内联预检与手动执行都会要求先恢复运行线程
  - 同一条运行线程健康门禁当前也会用于 `POST /api/strategies/{strategy_id}/execute`，避免真实模式下出现“预检被挡住、真正执行却还能下发”的分叉
  - 当桌面端手动触发策略执行但被门禁拦住时，当前会补写 `strategy.execution.blocked` 审计事件，方便最近执行摘要、审计流与 AI 复盘统一复用
  - 这类手动执行阻断当前也会升成 `system` 来源提醒，提醒中心能直接看到“手动策略执行被拦截”
  - 当后续同一策略的手动执行恢复成功后，这类阻断提醒当前会自动收起，并补写 `strategy.execution.blocked_resolved` 审计事件
  - 已有 `/api/strategies/stream`，用于给策略页和总览页提供 SSE 运行态快照
  - 已有 `GET /api/strategies/{strategy_id}/execution-preview`，会按工作台模式返回策略级执行预检
  - `demo/live` 策略目标仓位当前已改成“先按账户可用余额 × `risk_budget` 联动可新增仓位，再叠加可复用仓位/旧单释放占用，并按 Bybit `qtyStep / tickSize` 收敛”；若余额联动后的目标仍低于最小下单门槛，会直接显式阻断，并同步反映到 `target_position_size / position_alignment_detail`
  - 当上述 `risk_budget` 联动 sizing 被最小下单门槛拦住时，当前 `execution_preview` 还会带结构化的 `sizing_*` 字段，桌面端和后续 AI 可直接复用，不必再从提示文案里拆数字
  - 若当前同一策略在同品种上已有未成交、且后续会被复用、改单或撤销的可释放占用委托，这部分余额或保证金占用当前也会一并释放回策略 sizing 与真实预检
  - `perp` 真实顾问式预检当前也已改成只检查净新增保证金；减仓与等额反手不再按整笔名义价值误判为余额不足
  - `GET /api/integrations/bybit-private` 顶层 `last_error` 当前只保留主链路错误；可选 `spot` 类别与账户桶位诊断失败不会再把私有状态误写成异常
  - `GET /api/integrations/bybit-public` 当前也会返回公共实时链路的 `connected_spot / connected_linear / *_stale / last_error`，并按当前 watchlist 给出 `watched_symbol_diagnostics[]`
  - 已有统一的 `POST /api/strategies/{strategy_id}/execute`，当前会按模式自动分发：`paper` 写入纸面成交，`demo/live` 向 Bybit 提交真实限价委托
  - 对 `perp` 真实委托而言，若当前订单只会减仓或平仓、不会扩大或反手，系统当前会自动补上 `reduceOnly`；旧委托若缺少该标记，后续执行也会自动改单对齐
  - 后台 `strategy runtime` 循环当前已开始负责 `running + demo/live` 策略的自动真实委托下发；单纯打开策略页不会触发自动下单
  - 若当前真实策略委托的方向、数量、价格已经与最新信号一致，后台循环与手动执行都会直接复用旧委托，不再额外发起改单
  - 若 `live/demo` 策略配置了 `stop_loss_pct` 且当前真实仓位触发阈值，后台循环会自动撤掉遗留策略委托、升成 `P0` 系统提醒，并让策略级执行预检转为显式阻断
  - 当真实策略切入 `shadow / paused / watch` 等非执行状态时，后台循环会自动撤销该策略遗留的真实委托
  - 真实委托记录当前已保留 `origin(manual|strategy)` 与 `strategy_id`，交易记录页和历史订单窗口可直接区分手动单与策略单
  - 真实成交记录当前也会按 `private_order_metadata` 和新的 `strategy-{mode}-{strategy_id}-...` 形式 `orderLinkId` 还原 `manual / strategy` 来源
  - `live / demo / shadow` 策略当前在信号切换时会自动生成 `system` 来源提醒，同一策略旧的未确认信号提醒会自动收起
  - 当策略纸面执行被风控拦截时，当前会自动升成 `system` 来源提醒，而不只停留在审计日志
  - 带 `stop_loss_pct` 的 `paper` 策略当前会在本地自动止损平仓
  - 带 `cooldown_minutes` 的 `paper` 策略在止损后会进入冷却期，冷却结束前不会再次给出可执行预估
- 账户总览、持仓、委托和最近成交当前已开始优先使用 Bybit 私有 WebSocket 本地缓存，私有 REST 继续承担首帧与回退
- `live / demo` 真实执行当前会把 Bybit 私有 WS 的连通、鉴权和新鲜度一起作为硬门禁；私有链路失活时，策略预检、自动执行和手动策略执行都会统一阻断
- `live / demo` 真实执行当前也会把 Bybit 公共 WS 的连通、目标品种实时行情是否已到达、以及最近是否仍在刷新一起作为硬门禁；目标品种公共链路未连通、未收到首帧或已失活时，策略预检、自动执行和手动策略执行都会统一阻断
- 公共实时链路门禁当前也会自动升成策略级 `system` 提醒；恢复后会自动关闭提醒并补写恢复审计，提醒中心、审计页和 AI 复盘都能看到
- 后台自动执行在遇到公共/私有执行链路异常时，当前也会优先撤销遗留真实策略委托，再保持阻断状态，避免链路失活期间旧单继续挂在交易所侧
- 若真实模式下因外部干预或异常遗留多笔同策略挂单，后台当前也会优先自动清掉多余旧单，只保留最新目标委托
  - 手动 `POST /api/strategies/{strategy_id}/execute` 若因真实预检阻断返回 `409`，当前也会直接把原始建议拼进错误详情；同时阻断提醒和审计事件也会保留同一条建议
  - `demo / live` 顾问式预检与真实委托当前还会优先读取 Bybit `instruments-info`，本地先校验最小下单量、数量步长、价格步长和最小名义价值，尽量在提交前挡住明显无效的真实委托
  - 新闻事件页已开始优先拉取真实 Bybit 公告，并与本地宏观 / 市场 / AI 摘要新闻合并返回
  - 高影响 Bybit 公告会自动生成 `news` 来源提醒，并把提醒关联回新闻事件
  - 已有 `/api/market/stream`、`/api/ai/stream` 和 `/api/ops/stream` SSE 流，桌面端开始从轮询过渡到流式刷新
  - 已有 `/api/account/stream` SSE 流，交易记录页开始从分散轮询过渡到流式刷新

  - `paper_order.filled`、`paper_order.cancelled_all` 与 `manual_trade.positions_closed_all` 当前也会触发桌面通知，方便直接盯住本地 `paper` 执行结果
  - Electron 桌面壳当前已支持托盘常驻，可快速显示/隐藏窗口与退出应用
  - 已有 Bybit 私有 API 只读账户视图适配与本地配置入口
  - `/api/integrations/bybit-private` 当前会返回私有实时链路的启用、连接、鉴权与最近消息状态
  - 已把 Bybit 私有最近成交历史并入 `GET /api/trades`，交易记录页会优先显示真实成交，再叠加本地 Paper / 策略记录
  - 已有 `POST /api/trades/preview` 统一执行预检接口，桌面端手动交易窗口会先展示名义价值、可用余额变化、持仓变化和阻断原因，再决定是否真正写入 `paper`
  - `POST /api/trades/preview` 当前也支持 `demo / live` 顾问式预检，会基于当前 Bybit 私有账户余额和持仓返回动作、仓位影响和阻断原因

  - 已有 `POST /api/account/paper/orders`、`POST /api/account/paper/orders/cancel-all`、`POST /api/account/paper/orders/{order_id}/replace` 与 `POST /api/account/paper/orders/{order_id}/cancel`，可把 `paper` 限价单挂入本地委托簿、批量全撤、改价改量或撤单

  - 已有 `POST /api/account/paper/positions/close-all`，可在 `paper` 模式批量平掉全部本地持仓
  - 已有真实交易 POST 链路的安全探测接口
  - 已有 OpenClaw 本地配置读取与状态探测

  - 已支持真实终止当前 OpenClaw 任务，`cancel_job` / `cancel_all` / `enter_manual_override` 不再只是状态切换
- 高影响策略变更当前在落地后会自动排一条 `review_strategy_change` 任务，补齐“变更 -> 落地 -> AI 跟踪摘要”的闭环；提醒规则等轻量变更仍继续走 `reconcile_change_request`
- `review_strategy_change` 完成或失败后，当前会额外写入 `strategy.change.review.completed / failed` 审计事件，策略活动时间线已可直接复用
- 当真实执行问题被升成 `system` 提醒时，当前也会自动排一条 `review_strategy_issue` 任务，补齐“异常 -> 跟踪 -> AI 写回”的闭环
- `review_strategy_issue` 完成或失败后，当前会额外写入 `strategy.issue.review.completed / failed` 审计事件，策略活动时间线已可直接复用
- 上述两类“跟踪完成”审计事件当前也会带 `linked_review_id / linked_review_title / linked_review_period`，后续若增强日志页或活动流，优先直接复用这些元数据
- 策略页当前也已支持手动发起问题/变更跟踪，走 `POST /api/strategies/{strategy_id}/review`，并会补写 `strategy.review.requested` 审计事件；后续如果继续增强人工排障入口，优先复用这条接口而不是让前端自己拼 `AgentJobCreate`
- `review_strategy_change / review_strategy_issue` 当前在完成时还会补写一条单策略跟踪复盘，策略页二级窗和 `AI 复盘` 已可直接复用
  - `AI 复盘` 页当前已按“日报 / 回测复盘”和“策略跟踪”分开展示，后续新增单策略跟踪复盘应继续沿用这个分组，不要再混回主复盘流
  - `AI 复盘` 页当前也会展示最近的 `review_strategy_issue / review_strategy_change` 跟踪任务，便于同时看过程与结果
  - `AI 复盘` 页中的单策略跟踪与跟踪任务当前可直接跳转到对应策略活动窗口，后续若继续增强排障链路应复用这条跳转
  - `AI 复盘` 页中的“策略跟踪”当前支持按当前策略过滤，后续若补更多排障上下文，优先延续这个轻量过滤而不是再堆新页面
  - 策略活动二级窗当前也能直接跳回 `AI 复盘` 页，后续若继续增强单策略排障，优先沿用这条双向跳转
  - 策略活动二级窗与 `AI 复盘` 页里的跟踪任务当前也支持直接重试失败/已取消任务，后续若继续增强任务处理，优先沿用这条近场重试而不是强迫用户跳去 `AI 调度`
  - 跟踪任务完成后，策略活动接口当前也会带回关联的单策略复盘元数据，后续若继续增强结果展示，优先复用 `linked_review_*` 而不是再做前端时间线猜测
  - 策略活动二级窗与 `AI 复盘` 页里的跟踪任务当前也支持直接打开关联复盘结果；若任务已带 `linked_review_id`，前端会优先聚焦这条结果而不是只切页面
  - 复盘结果详情小窗当前还会直接显示 `source_job_*` 并支持反向打开对应 AI 任务，后续若继续增强排障链路，优先复用这条“结果 -> 任务 -> 策略”活动跳转
  - 策略活动二级窗与 `AI 复盘` 页中的跟踪复盘列表当前也支持直接 `打开任务`，后续若继续增强排障入口，优先沿用这条近场跳转
  - 系统日志/审计页当前也会复用这组 `linked_review_*` 元数据，后续若继续增强日志排障，优先沿用“直接打开结果”而不是要求用户手动切页定位
  - 对通用 `openclaw.job.completed` 事件，日志页当前也会兼容读取 `review_id / review_title / review_period`，避免只有策略跟踪任务能直达复盘结果

  - 真实策略委托在交易所侧成交 / 撤销 / 拒绝后，后台会自动补写对应审计事件，方便日志与复盘统一复用
  - 真实策略委托若被交易所拒绝，当前会自动升成 `system` 来源提醒，提醒中心可直接处理
  - 当后续真实策略委托恢复正常提交 / 成交后，旧的拒单提醒会自动收起，不会长期堆积
  - 若同一条真实策略在短时间内连续多次 `Rejected`，后台当前会自动进入“连续拒单冷却”，暂停自动执行并让策略预检直接返回阻断原因
  - `GET /api/control/snapshot` 与 `/metrics` 当前也会同步这层状态，便于总览和 Grafana 直接看到连续拒单中的策略数量与剩余冷却时间
  - 若真实策略委托长时间挂单未动，后台当前会自动识别“停滞挂单”，升成 `system` 来源提醒，并在自动执行路径中先撤掉旧单再补单
  - `GET /api/control/snapshot` 当前已带结构化 `execution_health`，后续总览、Grafana、AI 复盘优先复用这份聚合，不再各自解析零散提醒
  - `execution_health` 当前也会显式带出 `public_execution_channel_issue / public_execution_stale / public_execution_stale_seconds`，便于区分“公有行情链路异常”和“私有执行链路异常”
  - 当公有执行链路异常来自底层传输错误时，当前 `execution_health.top_issue_detail` 与策略级阻断文案也会直接附带最近一条公共 WS `last_error`，便于排障时快速区分“通道未连通”和“TLS / EOF / 代理”类错误
  - `GET /api/integrations/bybit-public` 当前也会补一层 `rest_reachable / rest_last_error / rest_tested_at / recommended_action`；当出现“REST 正常、WS 握手失败”时，可直接定位到本机代理 / VPN / TLS / 防火墙，而不是继续误判成交易所业务异常
  - `GET /api/integrations/bybit-private` 当前也会返回 `realtime_recommended_action`；若私有 REST 正常但私有 WS 失败，建议会直接收敛到本机网络、代理、TLS 与 Demo / Live 配置检查
  - Bybit 公共 WS 当前已把短暂空闲的 `recv(timeout=1.0)` 视为正常空转，不再因为 1 秒没消息就把 `linear / spot` 通道误判成断线；执行门禁仍按目标品种最近实时行情是否 stale 决定是否放行
  - `execution_health` 当前除 `top_issue` 外，也会带 `top_issue_strategy_id / top_issue_strategy_name / top_issue_symbol / top_issue_detail / top_issue_recommended_action`，后续前端与 AI 复盘应优先消费这层可定位信息
  - 当前 `execution_health` 还会带 `runtime_worker_running / runtime_worker_issue / runtime_last_error`，并已提供 `POST /api/runtime/strategy-worker/restart` 供桌面端直接恢复后台 `strategy runtime` 循环
  - 当前也已提供 `GET /api/runtime/strategy-worker/status`，用于单独查询后台运行线程的健康状态与恢复建议
  - 桌面端设置页与策略页当前优先使用这条独立状态接口驱动“恢复运行线程”按钮与状态说明，不再只靠总览快照间接推断
  - 桌面端设置页当前也支持直接保存本地控制设置，包括 `bybit_web_entry / api_base_url / default_mode / notification_channels / notification_quiet_hours_* / product_language / grafana_*`；普通桌面通知会遵守静默时段，`critical` 级提醒继续放行；OpenClaw `gateway_url / agent` 继续只读展示，因为真实运行态仍由本机外部配置驱动
  - 同内容的普通桌面通知当前也会自动做 2 分钟短时去重，避免同类提醒短时间重复刷屏；测试通知与 `critical` 级提醒继续直通，不受这条去重影响
  - 设置页当前也会直接展示 Bybit 私有只读配置文件路径、仓库示例文件路径，以及 OpenClaw 本机配置路径与 `openclaw` 命令可用性；在 Electron 桌面端里还可直接打开配置目录或示例文件，后续排障优先引导用户先用这组显式入口，不要只说“未配置”
  - 若手动恢复运行线程失败，当前会额外生成 `P1` 的 `system` 来源提醒“恢复运行线程失败”；后续成功恢复后会自动收起并写入恢复审计事件
  - AI 复盘当前在写入 `ReviewDocument` 时，也会自动把 `execution_health.top_issue / top_issue_detail / top_issue_recommended_action` 与运行线程问题补进风险列表，避免复盘遗漏真实执行门禁
  - 当前排队的 `generate_daily_review / generate_backtest_review` 任务上下文也会带 `execution_top_issue_symbol / execution_top_issue_detail`，便于后续重试与审计定位
  - 这两类复盘上下文当前还会带 `execution_top_issue_strategy_activity / review_strategy_activity`，后续若要增强 OpenClaw 复盘或排障，应优先复用这两份紧凑策略活动摘要
  - `generate_backtest_review` 当前会在任务入队时就固化 `review_strategy_activity`；后续生成提示词和写回 `ReviewDocument` 时会优先复用这份上下文，不再因稀疏上下文临时回拉 Bybit 实时链路。仅 `generate_daily_review` 仍保留最新执行健康兜底
  - 上述紧凑策略活动摘要当前也会显式带 `runtime.next_action` 和结构化 `execution_preview` 关键信息，包括 `recommended_action` 与 `sizing_*` 资金门槛字段，后续 AI 排障不必再从长文案里反推当前余额缺口
  - 当前也已提供 `GET /api/strategies/{strategy_id}/activity`，后续如果要给策略页补二级小窗或给 AI 复盘补单策略时间线，应优先复用这条聚合接口
  - 当工作台当前 `selected_mode` 与策略自身模式不一致时，这条活动接口当前也会优先补齐按该策略自身模式生成的 `execution_preview`，后续排障与 AI 复盘无需再强制切换工作台模式
  - 这条策略活动接口当前也会附带最近的策略相关 AI 任务摘要，便于直接看到 `review_strategy_change / generate_backtest_review` 等跟踪动作
  - 这条策略活动接口当前也会附带最近的 `review_strategy_issue` 摘要，便于直接回看单策略最近一次异常跟踪
  - 这条策略活动接口当前也会附带最近的单策略 AI 复盘摘要，策略页二级窗已经可以把“复盘 / 任务 / 执行”一起看
  - 这条策略活动接口当前还会附带 `latest_primary_review / latest_tracking_review / latest_tracking_job` 三个轻摘要字段，后续前端应优先复用，不要每次都重新切整份活动列表
  - 当前还会检测“线程仍在运行但长时间未刷新”的停滞状态，并把它统一归入 `execution_health.runtime_worker_stale / runtime_stale_seconds`
  - 当前也会检测“线程已经停止、但此前曾成功刷新”的未运行状态，并把它提升为“运行线程未运行”与 `system` 来源提醒
  - 线程异常或停滞当前会直接升成 `system` 来源提醒，恢复运行线程后会自动收起并写入恢复审计事件

  - 前端已在 AI 调度页挂上 Grafana / 指标预览小窗，当前用于系统监控而不是主交易图
