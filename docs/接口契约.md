# 接口契约

本文档描述当前桌面控制端与本地控制服务之间的主要数据结构和接口语义，方便后续让 AI 或新线程继续开发时保持一致。

## 核心模型

### `ControlSnapshot`

首页控制总览的统一快照，包含：

- 资产指标
- 风险指标
- 策略指标
- AI 调度状态
- 告警摘要
- 待处理任务
- 当日表现

### `ChangeRequest`

前端任何“会改变系统状态”的操作，都先写成 `ChangeRequest`。

典型场景：

- 策略参数修改
- 策略启停
- 风控边界调整
- 提醒规则修改
- 回测发起
- AI 调度控制

状态流转：

- `draft`
- `queued`
- `running`
- `applied`
- `failed`
- `rolled_back`

### `AgentJob`

量化层或桌面端发送给 OpenClaw 的结构化任务。

关键字段：

- `job_type`
- `context`
- `allowed_actions`
- `timeout`
- `idempotency_key`
- `writeback_target`

### `SchedulerCommand`

AI 调度硬控制指令，固定支持：

- `pause`
- `resume`
- `cancel_job`
- `cancel_all`
- `freeze_publish`
- `enter_manual_override`

### `BacktestRun`

回测任务记录，统一保存：

- 策略版本
- 品种范围
- 时间范围
- 数据粒度
- 手续费模型
- 滑点模型
- 参数快照
- 收益率、回撤、胜率、成交统计

### `WorkspacePreferences`

桌面控制端的工作台状态快照，当前用于保存：

- 默认页面
- 布局方案
- 当前模式
- 当前品种
- 当前策略
- 总览卡片顺序
- 总览卡片显隐
- 最近保存时间

### `MarketDetail`

行情详情当前除基础 K 线、盘口和统计数据外，还包含：

- `source`：当前数据来源，`bybit_rest` 或 `mock`
- `updated_at`：最近一次行情更新时间

### `ExecutionEvent`

统一审计事件模型，是后续排查问题的核心事实来源。

建议长期保持这些字段稳定：

- `event_type`
- `severity`
- `source`
- `symbol`
- `strategy_id`
- `payload`
- `trace_id`
- `occurred_at`

## 当前 API

### 健康检查

- `GET /health`

### 控制总览

- `GET /api/control/snapshot`

### 行情

- `GET /api/market/watchlist`
- `GET /api/market/{symbol}`

说明：

- 当前优先从 Bybit 公共 REST API 获取实时行情
- 如果外部行情拉取失败，则自动回退到本地 mock 数据
- 这里的 API 行情入口与网页登录入口用途不同：
  - 网页登录、账户设置、API Key 创建继续按 `https://www.bybit-global.com/`
  - 程序获取行情继续使用 `api.bybit.com` 等 API 域名

### 策略

- `GET /api/strategies`

### 回测

- `GET /api/backtests`
- `POST /api/backtests`

### ChangeRequest

- `GET /api/change-requests`
- `POST /api/change-requests`

### AI 调度

- `GET /api/ai/scheduler`
- `POST /api/ai/scheduler/commands`
- `GET /api/ai/jobs`
- `POST /api/ai/jobs`

### 新闻 / 提醒 / 交易 / 复盘 / 审计

- `GET /api/news`
- `GET /api/alerts`
- `GET /api/account/overview`
- `GET /api/account/positions`
- `GET /api/account/orders`
- `GET /api/trades`
- `POST /api/trades/manual`
- `GET /api/ai/reviews`
- `GET /api/audit/events`

当前补充说明：

- `GET /api/account/*` 在未配置 Bybit 私有 API Key 时，会稳定回退到 mock 数据
- `GET /api/account/*` 在已配置私有 Key 且真实账户为空时，会返回真实空结果，不再错误回退到 mock 持仓或 mock 委托
- `POST /api/trades/manual` 当前只接受 `paper` 模式；`demo` / `live` 会明确返回拒绝，避免把占位链路误认为真实下单
- `POST /api/integrations/bybit-private/probe-trade` 会发送故意无效的参数到 Bybit 交易接口，用于验证签名、认证和交易 POST 链路，不用于真实下单

### 设置与 OpenClaw 状态

- `GET /api/settings`
- `GET /api/workspace/preferences`
- `POST /api/workspace/preferences`
- `GET /api/integrations/bybit-private`
- `POST /api/integrations/bybit-private/probe-trade`
- `GET /api/integrations/openclaw`

## 约束规则

### 交易执行

- 手动交易和自动交易都必须由量化层完成
- OpenClaw 不直接执行交易
- 风控必须在量化层生效
- 当前控制端的手动交易接口只开放 Paper 路径，直到真实执行引擎接通

### Bybit 域名

- 网页端入口固定使用 `https://www.bybit-global.com/`
- API 接口域名与网页端入口分离
- 账户、持仓、委托等私有数据必须通过 Bybit 私有 API + API Key 访问，不能直接复用网页登录态

### 前端与 OpenClaw 的关系

- 前端不直接给 OpenClaw 自然语言大指令作为唯一依据
- 前端应该优先发送结构化任务
- OpenClaw 主要消费 `ChangeRequest` 和 `AgentJob`

### 工作台状态同步

- 工作台状态先保存在桌面本地缓存
- 服务在线时再同步到 `WorkspacePreferences`
- 这样既保证本机重开可恢复，也方便后续 AI / 新线程读取当前控制端习惯

## 后续扩展建议

如果后续要替换 mock 服务为真实量化核心，优先保持这些接口路径和数据模型不变，让桌面端保持最小改动。
